# ระบบพิกัดจัดส่ง กระดานโน้ต และไรเดอร์

## เลขออเดอร์ รูปยืนยัน และค่าจัดส่ง

- Kitchen board ซ่อนแผนที่ไว้ กดไอคอน GPS ข้างเลขออเดอร์ในรายละเอียดเพื่อเปิดหรือปิด
- เลขที่แสดงวนจาก `BK001` ถึง `BK500` แล้วกลับ `BK001` รหัสออเดอร์ภายในยังไม่ซ้ำกัน ระบบเก็บตัวนับถาวรใน `order-counters` และจองเลขใน transaction ของออเดอร์
- ไรเดอร์ต้องแนบภาพ JPEG, PNG หรือ WebP ไม่เกิน 5 MB ก่อนยืนยันส่งสำเร็จ บนอุปกรณ์ที่รองรับ ปุ่มเลือกภาพจะเปิดกล้องหลัง รูปผูกกับออเดอร์และไรเดอร์เจ้าของงาน ตรวจชนิดภาพจริง และไม่อนุญาตนำรูปจากงานอื่นมาใช้
- รูปเป็นข้อมูลส่วนตัว เก็บใน `data/delivery-photos/` และเปิดได้เฉพาะเจ้าของงาน ลูกค้าของออเดอร์ และทีมร้านที่มีสิทธิ์ ต้องสำรองโฟลเดอร์นี้พร้อมฐานข้อมูลด้วย
- ยอดค่าจัดส่งสะสมรวมจากงานของไรเดอร์ที่มีสถานะส่งสำเร็จทั้งหมด ไม่รวมงานยกเลิกหรืองานที่ยังไม่เสร็จ ยอดนี้เป็นยอดค่าส่งสะสม ไม่ใช่สถานะการจ่ายเงิน
- การรับงานใช้เงื่อนไขงานพร้อมและยังไม่มีไรเดอร์ที่เซิร์ฟเวอร์ ปุ่มฝั่งไรเดอร์ป้องกันการกดซ้ำระหว่างดำเนินการ ทดสอบแล้วว่าแข่งรับงานมีผู้สำเร็จเพียงคนเดียว และรับหรือส่งงานเดิมซ้ำไม่สำเร็จ

คำสั่ง `npm.cmd run db:upgrade` สำรองฐานข้อมูลก่อนเพิ่ม schema ที่สร้างจาก Payload โดยไม่สร้างตารางเดิมทับ หากอัปเกรดฐานข้อมูลรุ่นเก่าที่มีออเดอร์แล้ว ให้หยุดเว็บและรัน `npm.cmd run payload -- run scripts/maintenance/backfill-order-labels.ts` หลังอัปเกรด เพื่อเติมเลขแสดงผลให้รายการเก่าโดยเก็บรหัสอ้างอิงเดิมไว้

## ทดลองใช้งาน

เปิดเว็บไซต์จาก URL Local ที่หน้าต่างเซิร์ฟเวอร์แสดง แล้วใช้บัญชีตัวอย่าง:

| บทบาท | อีเมล | หน้าเข้าสู่ระบบ |
|---|---|---|
| ลูกค้า | customer@burken.co | /login |
| พนักงาน | staff@burken.co | /login |
| ผู้ดูแลแอป | admin@burken.co | /login |
| ไรเดอร์ | rider@burken.co | /rider/login |

รหัสผ่านตัวอย่างทุกบัญชี: `Burken123!` บัญชีไรเดอร์ถูกสร้างตามการอนุญาตของผู้ใช้ บัญชีผู้ดูแลแอปและบัญชี CMS ที่ /admin เป็นคนละระบบสิทธิ์ตามเดิม

1. ลูกค้าเพิ่มอาหารในตะกร้า เลือกจัดส่ง แล้วเลือกวิธีระบุจุดส่ง: ใช้หมุด (ตำแหน่งปัจจุบันหรือวางพิกัดแล้วปักหมุด) โดยช่องที่อยู่จะจางและกรอกไม่ได้ หรือเลือกกรอกที่อยู่โดยไม่ต้องใช้หมุด ตรวจจุดส่งก่อนยืนยัน
2. พนักงานเปิด /portal ดูแท็บออเดอร์เข้า บนจอกว้างตั้งแต่ 1100px ขึ้นไปวางโน้ตได้ 4 แผ่นต่อกรอบ ใช้ล้อเมาส์เลื่อนซ้าย–ขวาภายในกรอบเพื่อดูแผ่นถัดไป ส่วนรายการอาหารยังเลื่อนขึ้น–ลงได้
3. กดโน้ตเพื่อปักหมุดเฉียง เลื่อนโน้ตที่เลือกมาชิดซ้าย และแทรกรายละเอียดทางขวา รายการอาหารในกรอบเลื่อนลงช้า ๆ พักที่ท้าย แล้วกลับบนสุดวนใหม่ หยุดเลื่อนได้ด้วยปุ่มหรือวางเมาส์/โฟกัสบนรายการ มี scrollbar สำหรับอ่านเอง
4. พนักงานกดเริ่มปรุง แล้วอาหารพร้อม ออเดอร์รับที่ร้านกดส่งมอบได้ ส่วนออเดอร์จัดส่งจะเข้าสู่รายการงานพร้อมรับของไรเดอร์เมื่อมีหมุดหรือที่อยู่จัดส่ง
5. ไรเดอร์รับงาน เปิดเส้นทางใน Google Maps กดรับอาหารแล้ว/เริ่มนำส่ง และกดยืนยันส่งถึงลูกค้าเมื่อส่งจริง
6. ลูกค้าดูสถานะกับหมุดของออเดอร์ในพอร์ทัลได้ พอร์ทัลรีเฟรชข้อมูลทุก 10 วินาทีขณะหน้าเปิดอยู่

มีแอนิเมชั่นเข้าสู่หน้าและเปิดรายละเอียดแบบสั้น รองรับการตั้งค่า Reduce Motion ของอุปกรณ์ โดยไม่เลื่อนรายการอัตโนมัติเมื่อเปิด Reduce Motion

## Google Maps เมื่อยังไม่มี API key

ใช้งานตำแหน่งปัจจุบัน พิกัด ลิงก์ Google Maps แบบเต็ม การดูแผนที่พิกัด และลิงก์นำทางได้ Google Maps ต้องใช้อินเทอร์เน็ต ส่วนการอ่านพิกัดปัจจุบันขึ้นกับการอนุญาตของเบราว์เซอร์

ตัวอย่างพิกัด: `13.756300, 100.501800` ลิงก์สั้น maps.app.goo.gl ที่ไม่มีพิกัดในข้อความต้องเปิดใน Google Maps แล้วคัดลอกพิกัดหรือลิงก์เต็มก่อน ระบบไม่ตีความจุดกึ่งกลางแผนที่เป็นตำแหน่งปัจจุบันโดยอัตโนมัติ

หากเพิ่ม Google Maps JavaScript API key ภายหลัง ให้ตั้ง `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` ใน .env.local และ build ใหม่ จากนั้นจึงคลิกบนแผนที่หรือลากหมุดในเว็บได้ อาจตั้ง `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID` เพิ่มสำหรับ Map ID ของโครงการ Key นี้ใช้ในเบราว์เซอร์ตามรูปแบบ Google Maps จึงต้องจำกัด HTTP referrer และ API ให้เหมาะกับเว็บไซต์ ห้ามใช้ค่าคีย์ของบริการฝั่งเซิร์ฟเวอร์แทน

เอกสาร Google: https://developers.google.com/maps/documentation/urls/get-started และ https://developers.google.com/maps/documentation/javascript/load-maps-js-api

## ข้อมูลและสิทธิ์

เพิ่มช่องพิกัดและความสัมพันธ์กับไรเดอร์แบบ optional เพื่อเก็บออเดอร์เก่าไว้เหมือนเดิม ออเดอร์จัดส่งใหม่ต้องมีพิกัดที่ถูกต้องหรือที่อยู่ที่กรอกก่อนสร้าง หากส่งพิกัดมาจะตรวจความถูกต้องเสมอ ออเดอร์ที่มีเพียงที่อยู่สามารถให้ไรเดอร์รับงานได้ โดยลิงก์ Google Maps จะค้นหาจากที่อยู่และไรเดอร์ต้องตรวจผลค้นหาก่อนนำทาง

การรับงานและเปลี่ยนสถานะตรวจสิทธิ์และสถานะเดิมที่เซิร์ฟเวอร์ ไรเดอร์อ่านงานที่พร้อมรับและงานของตนเองได้ รับแทนคนอื่นไม่ได้ และข้ามขั้นตอนส่งสำเร็จไม่ได้ ราคาคำนวณจากข้อมูลเมนูจริงฝั่งเซิร์ฟเวอร์ตามเดิม

สำรองฐานข้อมูลก่อนอัปเกรดไว้ใน `data/backup-delivery-*.db` การอัปเกรดชุดนี้ติดตั้งแล้ว คำสั่ง `npm.cmd run db:upgrade` ตรวจและข้ามเมื่อพบช่องครบ จึงไม่ push schema ซ้ำทุกครั้งที่เปิดโหมดพัฒนา ฐานข้อมูลใหม่จะเริ่มสร้าง schema เมื่อเปิดเว็บครั้งแรกด้วย scripts/run.mjs

## การตรวจสอบ

```powershell
npm.cmd run build
npm.cmd run verify:delivery
npm.cmd run verify:local
```

verify:delivery สำรองข้อมูลจริงไปสร้างฐานข้อมูลสำเนาใหม่ใน data/delivery-verification/ ทุกครั้ง แล้วสร้างบัญชีและออเดอร์เฉพาะในสำเนา ทดสอบพิกัด สิทธิ์ สถานะครัว การล็อกอินพร้อมกัน และไรเดอร์สองคนรับงานพร้อมกัน โดยไม่เพิ่มออเดอร์ทดลองลงฐานข้อมูลจริง

รอบนี้ตรวจระบบผ่าน HTTP กับเซิร์ฟเวอร์จริง ยังไม่ได้ตรวจภาพหรือแอนิเมชั่นด้วยเบราว์เซอร์ เนื่องจากไม่มีเบราว์เซอร์เชื่อมต่อ Google Maps แบบคลิก/ลากยังไม่สามารถทดสอบจริงได้เพราะยังไม่มี API key
