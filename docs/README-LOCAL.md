# เปิดเว็บไซต์นอก Figma Make

โปรเจกต์นี้รันด้วย Next.js + Payload + SQLite บนเครื่อง Windows ได้โดยไม่ต้องเปิด Figma หรือใช้ FIGMA_EID

## วิธีเปิด

ดับเบิลคลิก `start-production.cmd` แล้วคลิกลิงก์ Local ที่แสดงในหน้าต่าง เช่น http://127.0.0.1:3000

หากมีเว็บใช้พอร์ต 3000 อยู่แล้ว โปรแกรมจะเลือกพอร์ตว่างถัดไป เช่น 3001 ให้ดู URL ที่แสดงจริงในหน้าต่างเซิร์ฟเวอร์ และเปิดหน้าต่างนั้นไว้ขณะใช้งาน ปิดเว็บด้วย Ctrl+C

- หน้าร้าน: `/`
- สมัครสมาชิกและเข้าสู่ระบบ: `/login`
- พอร์ทัลสมาชิก: `/portal`
- แอดมิน: `/admin`

บัญชีแอดมินและฐานข้อมูลเดิมถูกเก็บไว้ ใช้อีเมลและรหัสผ่านเดิมในการเข้าสู่ระบบ หากเซสชันเดิมหมดอายุ ให้เข้าสู่ระบบใหม่ การเปิดหน้าเว็บต้องมีเซิร์ฟเวอร์ Node.js ทำงาน ไม่สามารถเปิดไฟล์ TSX ด้วยการดับเบิลคลิกได้

## คำสั่งใน PowerShell

```powershell
# เปิด production build ที่ทดสอบแล้ว
.\start-production.cmd

# เปิดโหมดพัฒนา
.\start-local.cmd

# สร้าง build ใหม่หลังแก้โค้ด
npm.cmd run build

```

หากติดตั้ง dependencies ใหม่:

```powershell
corepack.cmd pnpm@10.34.3 install --frozen-lockfile
npm.cmd run setup
```

สำหรับฐานข้อมูลใหม่ ให้รัน `npm.cmd run dev` ครั้งแรกเพื่อสร้าง schema ก่อน build

## ข้อมูลที่ต้องสำรอง

- `data/burken.db` ฐานข้อมูลจริง
- `data/delivery-photos/` รูปยืนยันการจัดส่งที่เป็นข้อมูลส่วนตัว
- `media/` รูปภาพที่อัปโหลด
- `.env` ค่าลับสำหรับยืนยันตัวตน ห้ามเผยแพร่ไฟล์นี้

เก็บข้อมูลเหล่านี้ไว้พร้อมกันและสำรองขณะปิดเซิร์ฟเวอร์ มีสำเนาฐานข้อมูลก่อนปรับอยู่ใน `data/backup-before-standalone-*.db`

## ขอบเขตการเข้าถึง

ค่าเริ่มต้นเปิดเฉพาะเบราว์เซอร์บนเครื่องนี้ ไม่มีการเผยแพร่สู่สาธารณะ หากต้องการใช้ผ่าน Wi-Fi เดียวกัน สามารถกำหนด HOST เป็น 0.0.0.0 และ PORT เป็นพอร์ตที่ต้องการก่อนรัน แล้วใช้ IP ของเครื่องเซิร์ฟเวอร์จากอุปกรณ์อื่น การเปิดผ่านอินเทอร์เน็ตต้องจัดเตรียมโฮสติ้งและ HTTPS เพิ่มเติม SQLite และโฟลเดอร์ media ต้องอยู่บนพื้นที่เก็บข้อมูลถาวร

ยังไม่ได้ตั้งบริการส่งอีเมลสำหรับลืมรหัสผ่าน เมนู 4 รายการที่มีอยู่เป็นข้อมูลตัวอย่างจากการติดตั้งก่อนหน้า

## ส่วนพิกัดจัดส่งและไรเดอร์ที่เพิ่มล่าสุด

ดูวิธีใช้กระดานโน้ต การเลือกพิกัด และบัญชีไรเดอร์ใน [DELIVERY-AND-RIDER.md](DELIVERY-AND-RIDER.md) โปรเจกต์ใช้ Node.js 24 ขึ้นไป คำสั่งอัปเกรด schema รุ่นนี้รันซ้ำได้โดยไม่เปลี่ยนข้อมูลที่ติดตั้งแล้ว และไม่ push schema ทุกครั้งที่เปิดโหมดพัฒนา

## ตรวจสอบการเข้าสู่ระบบก่อนสั่งอาหาร

หัวเว็บแสดงชื่อบัญชีเมื่อเข้าสู่ระบบแล้ว หน้าร้านตรวจเซสชันจาก `/api/app/session` โดยไม่ใช้แคช ก่อนเพิ่มสินค้าและยืนยันออเดอร์ ผู้ที่ยังไม่เข้าสู่ระบบจะเห็นป๊อปอัปพร้อมลิงก์เข้าสู่ระบบและสินค้าไม่ถูกเพิ่ม หากตรวจเซสชันไม่ได้จะหยุดการเพิ่มสินค้าและให้ลองตรวจสอบใหม่ ตะกร้าเก็บแยกตามบัญชีลูกค้าและไม่โหลดตะกร้าเก่าที่ไม่มีเจ้าของ

Server Action และ collection ตรวจสิทธิ์ลูกค้าซ้ำอีกครั้ง การส่งคำขอ REST โดยตรงหรือใส่ role/overrideAccess ในข้อมูลไม่ให้สิทธิ์สั่งอาหาร การออกจากระบบเพิกถอนเซสชันในฐานข้อมูลด้วย
